## baby-farm v12：萌可"突然又不透明了"——根因 & 永久修复

**用户反馈**："萌可宠物修改，直接使用 萌可1.png 这个透明图，所有这个萌可都要透明的，加入动态，怎么突然又不透明了"（附 1000037364 透明 PNG + 实际部署截图）

### 根因诊断（双重叠加）
1. **真根因**：之前 v11 删了 `pet-halo` 元素但漏了 `pet-stage` 容器层——
   - `.pet-stage` 是 `background:transparent` 的 144×156 容器
   - 它嵌在 `.pet-card`（`linear-gradient(170deg,#FFF0F6,#FFE6F0)` 浅粉渐变）里
   - **透明容器透出粉色卡片背景** → 萌可站立处看到的就是粉方框，体感像"halo 又回来了"
2. **缓存根因**：浏览器/手机缓存了旧版 HTML（v9-v10 含 halo CSS），CDN 没强制刷新
3. **PNG 验证**：用 Python 手动解 PNG 像素——`color_type=6 RGBA`，20160 像素里 10436 个 A=0（51.8% 真透明）、9724 个 A=255、**0 个半透明**——PNG 本身完全干净
4. **halo 残留排查**：grep `pet-halo/petGlow/petHalo` 各 1 处，全部在 CSS 注释里说明已删除，无真实样式

### 修复方案（v12）
| 改动 | 效果 |
|---|---|
| `.pet-card` 加 `position:relative; overflow:hidden` | 防止舞台区被外部粉色渗入 |
| `.pet-stage` `background` 改为 `radial-gradient(circle at 50% 78%, #ffffff 0→38%, rgba(255,255,255,.55) 60%, transparent 100%)` | 中心纯白、外缘渐变透明，与粉色卡片自然过渡，**不出现硬方框** |
| `.pet-img-wrap` `background:#ffffff` + 浅阴影 | 兜底白底+轻微立体感，萌可站立在干净白色 |
| 图片 inline `style="background:transparent"` + `onerror` fallback | 强兜底：图片自身不继承任何容器底色 |
| `<img>` 加 `loading="eager" decoding="sync"` | 首屏立即渲染，避免加载延迟导致的"白底闪烁"被误判为 halo |
| head 加 `CDN-Cache-Control: no-store` + `Cloudflare-CDN-Cache-Control: no-store` | 拦截代理/CDN 缓存 |
| `WB_BUILD` v11 → **v12** | 强制图片 `?v=v12` 重新加载，绕开 HTTP 缓存 |

### 关键教训
- **"透明"≠"没有背景"**——透明容器透出父级彩色背景 = 看起来有背景色。要彻底"看不见背景"必须给容器自身一个**非父级颜色**的纯色（白/全屏色），或用 `clip-path` 抠掉父级背景
- **CSS 注释里残留旧类名**(`pet-halo/petGlow/petHalo`)是排查干扰项——它们**不渲染**但容易让 grep/搜索误判
- **强制刷新双保险**：meta no-cache + WB_BUILD 升版 + src `?v=` + CDN-Cache-Control 四层叠加才能 100% 绕开 CDN 缓存
- **`nul` 是 Windows 保留设备名**，所有 rm/del/mv/shutil.unlink 都会失败，只能用空文件夹部署绕过
- **agentos-app.net 主域会被 DNS 黑洞到 0.0.0.1**，但 `*.agentos-app.net` wildcard 正常——deploy 工具内部可能用了主域导致间歇性 fetch failed，需重试
